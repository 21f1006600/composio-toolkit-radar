05 / Research architecture

The pipeline separates documentation discovery, structured extraction, verification and publication.

Application registry
→
Composio + Tavily
→
Document retrieval
→
Gemini researcher
→
Verification agent
→
SQLite + Report

01. Targeted discovery

Separate search queries investigate authentication, API access, capabilities and MCP implementations. Search execution uses the Composio SDK.

02. Passage grounding

Retrieved documents are divided into identifiable passages. The research agent references passage IDs instead of reproducing quotations.

03. Semantic verification

A separate model call evaluates claims and structured fields against the retrieved evidence. Unsupported values are conservatively removed.

04. Corrective research

Verification failures generate targeted follow-up queries. Candidate attempts are evaluated and the strongest result is selected.

05. Resumable execution

SQLite stores research results, attempt histories and execution status. Interrupted batches can resume without repeating completed applications.

06. Conservative publication

Unresolved fields remain unknown rather than being filled with unsupported assumptions.

What changed?

V2 — Context optimization: Increasing and reorganizing research context did not consistently improve completeness.

V3 — Passage grounding: Replacing generated quotations with passage references improved evidence handling. One application encountered a service failure.

V4 — Verification resilience: Stricter classification instructions and transient-error retries produced the strongest three-application completeness benchmark.

07 / Limitations and next steps

Documentation-based assessment: API credentials and live business operations were not tested for every application.

Source coverage: Dynamic pages, inaccessible documentation and product naming ambiguity can limit research quality.

Verification limitations: Model-based semantic verification can miss factual errors and claim-to-field inconsistencies.

MCP discovery: A not-found classification indicates that research did not identify a relevant implementation. It does not establish that none exists.
